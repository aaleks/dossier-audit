# Canonical example values

Every example table in `specs/` draws from this set. One vocabulary across seven
specs means an example row transcribes straight into `tests/fixtures/` without a
translation step, and two rules describing the same item are visibly about the
same item.

Do not invent a new incident key for a new example. Add to this file instead.

## The PDF postmortem corpus

Ten fabricated IT incident postmortems under
`tests/fixtures/documents/postmortems/`, generated by the script beside them and
committed as PDFs. Five are complete; five each carry a known defect. Layouts
differ on purpose -- corporate template, engineering plain text, wiki export,
two-column, landscape one-pager, scanned-looking memo -- so a converter is
exercised against more than one document shape.

They exist so that a stage claiming "the action plan is present" can be shown to
be wrong, and so that abstention has real absences to be scored against (spec
007). No rule cites them yet.

| Key | File | State |
|---|---|---|

**Per-field gold answers are deliberately not recorded here.** Spec 007 has fixed
no gold format yet and every one of its rules is `NOT MET`; writing expected
values before that is inventing a threshold by another name. What is recorded is
which document is defective and how, which is what the corpus was built to say.

## Converters

An id and a version, in the pair `(media type, kind)` each one claims. The
versions are deliberately unequal and deliberately not `1.0.0`: R5.4 is about
what happens when one of them moves, and a table of identical versions hides an
example that reads the wrong field.

| Converter | Claims | Version |
|---|---|---|
| `pdf-markdown` | `(application/pdf, markdown)` | `1.3.0` |
| `pdf-images` | `(application/pdf, page_images)` | `0.9.1` |
| `markdown-text` | `(text/markdown, markdown)` | `1.0.0` |

`1.4.0` is `pdf-markdown` after an improvement — the raised version every R5.4
example refers to.
