## 1 · Welcome

**What dossier does**

- Collects documents from folders, Jira, Confluence and websites
- Freezes each one as an immutable snapshot
- Runs a pipeline of prompt steps over them
- Checks that every answer quotes its source
- Scores the answers against answers a person verified

> Welcome to dossier. dossier is a command-line tool for auditing documents with a language model, and for proving how well it did. It collects documents from your sources, and freezes each one as a snapshot that never changes. Then it runs a pipeline of prompt steps over them, and checks that every answer quotes the document it came from. Finally, it scores those answers against answers a person verified.

**In the next ten minutes**

- sync  →  convert  →  plan  →  run  →  eval

> In the next ten minutes, we'll take a folder of four incident notes all the way to a score. Then we'll change a prompt, and watch dossier catch the regression it causes. Everything you'll see runs offline, on your own machine, at zero cost. Every command is typed live, and every output is real. Let's start.

## 3 · Where the model is served

> dossier talks to every model over one OpenAI-compatible route. The .env file says only where that route is served, and with which key.

```console
~/quickstart $ cat .env
# Where the model is served. Which model answers is pipeline.yaml's business.
DOSSIER_OPENAI_URL=http://127.0.0.1:8199/api
DOSSIER_OPENAI_API_KEY=stub
```

> In this course, that address is a stub server on this machine. It answers from a file of prepared replies. It's the same code path a real model takes, but it's free, and it gives the same answer every time. Later, you'll point this line at your own OpenWebUI, and nothing else changes.

## 4 · Sync and snapshots

> The first command is sync. It asks each source what it holds, and freezes every new document as a snapshot, named by the hash of its content.

```console
~/quickstart $ dossier sync incident-audit
incidents-manual  0 known · 0 changed · 4 new -> 4 fetched
ledger updated · 4 new snapshots · 0 tombstoned
```

> Four new documents, so four new snapshots. The ledger now remembers each one.

> Let's run it again.

```console
~/quickstart $ dossier sync incident-audit
incidents-manual  4 known · 0 changed · 0 new -> 4 fetched
ledger updated · 0 new snapshots · 0 tombstoned
```

> Four known, nothing changed, nothing new. Sync only ever stores what changed.

> Now a colleague adds a line to one of the notes.

```console
~/quickstart $ echo "- 2026-03-05: post-mortem held." >> inbox/incidents/PLAY-1001.md
```

> And we sync once more.

```console
~/quickstart $ dossier sync incident-audit
incidents-manual  4 known · 1 changed · 0 new -> 4 fetched
      PLAY-1001.md  6bdb8cad3ebd2dcf76a24acdf1d36b55a5cda49f0a7222c9809044573892b1d0 -> 913ff1d29243d2103a061181450c68fdf8b6b0e344b1f8cec91517f998fc5411
ledger updated · 1 new snapshots · 0 tombstoned
```

> One document changed, and it got a new snapshot, with a new hash. The old snapshot is never overwritten. So any run that read the old version can still be replayed, exactly as it was.

## 5 · A pipeline

> A pipeline is plain data, in its own folder.

```console
~/quickstart $ cat pipelines/incident-audit/pipeline.yaml
# A pipeline is data: the sources it reads, the model that answers, its steps.
# Its name is its directory's name: incident-audit.
sources: [incidents-manual]

model: openai:gpt-5.4-mini

steps:
  - id: extract
    prompt: prompts/01_extract.md
    input: documents
    mode: per_file
    output: schemas/incident.yaml
```

> It names the sources it reads, and the model that answers: gpt-5.4-mini. It has one step, extract, which runs once per file. The step has a prompt, and an output declaration.

> The output declaration lists the fields to extract.

```console
~/quickstart $ cat pipelines/incident-audit/schemas/incident.yaml
# The fields the extract step asks for. The kind decides how a field is scored.
fields:
  loss_amount:      {kind: amount, currency: CHF}
  resolution_date:  {kind: date}
  severity:         {kind: enum, values: [minor, major, critical]}
  affected_systems: {kind: reference}
```

> Four fields, each with a kind. An amount, a date, an enum with three allowed values, and a reference. The kind decides how an answer is scored later. An amount is compared as a number, and a date only when it can't be misread.

> And here's the prompt.

```console
~/quickstart $ cat pipelines/incident-audit/prompts/01_extract.md
Extract the requested fields from the incident note below.

Every non-null value must carry the document key, the page where the document has
pages, and the exact sentence the value came from. If a field is not stated in the
note, return it as null with a reason. Do not infer, and do not guess.

<source_document>{{documents}}</source_document>
```

> Every value must quote the exact sentence it came from, or be null with a reason. No guessing. That quote is how dossier checks that an answer is grounded in the document.

## 6 · Convert, plan and run

> Before a model can read a document, it has to be text. Convert does that, and caches the result.

```console
~/quickstart $ dossier convert incident-audit
incidents-manual  4 held · 4 converted · 0 cached
cache updated · 4 converted · 0 cached
```

> Markdown is nearly free. PDFs, web pages, screenshots and scans each have a converter of their own.

> Before spending anything, ask for the plan.

```console
~/quickstart $ dossier run incident-audit --plan
incident-audit  4 document(s) · model openai:gpt-5.4-mini
no previous run to compare against
! extract: new
1 of 1 step(s) would run · nothing written
```

> One step would run, and the plan says why: it's new, because there's no previous run. A plan writes nothing to disk, so it's always safe to ask.

> Now the real run. Four documents, one model call each.

```console
~/quickstart $ dossier run incident-audit
run 20261011T130755Z-b7cd · ~/quickstart/runs/20261011T130755Z-b7cd/manifest.json
  extract: 4 document(s) · 0 from cache · 0 failed · 1,581 tokens in · 644 out
```

> Every run gets an id, and a manifest. The manifest pins exactly what the run read. Each snapshot, the prompt, the output declaration, and the model. The run also counts the tokens it spent, so you know what it cost.

> Let's look at what came back for the first note.

```console
~/quickstart $ head -n 16 runs/20261011T130755Z-b7cd/extract/PLAY-1001.md.json
{
  "document": "PLAY-1001.md",
  "fields": [
    {
```

> Each field has a value, a confidence, and the exact text it was read from. dossier checked that this text really appears in the note. An answer that quotes something the note doesn't say is not accepted.

## 7 · The cache

> What happens if we run it again?

```console
~/quickstart $ dossier run incident-audit
run 20261011T130756Z-4d36 · ~/quickstart/runs/20261011T130756Z-4d36/manifest.json
  extract: 4 document(s) · 4 from cache · 0 failed
```

> Four answers from the cache. Each answer is stored under a key made of everything that could change it. Same snapshot, same prompt, same model: same key.

> The stub logs every request it receives.

```console
~/quickstart $ wc -l < model-calls.jsonl
4
```

> Four requests, all from the first run. The second run didn't ask the model anything. On a real model, that's time and money saved, and an answer you can reproduce.

## 8 · Scoring against gold

> So how good are these answers? To know, you need answers a person has checked.

```console
~/quickstart $ cat gold/incidents/PLAY-1001.json
{
  "document": "PLAY-1001.md",
  "verified_by": "a.aleks",
  "verified_at": "2026-09-17",
  "fields": {
    "loss_amount":      {"value": 18400.00, "currency": "CHF"},
    "resolution_date":  {"value": "2026-03-04"},
    "severity":         {"value": "major"},
    "affected_systems": {"value": "checkout-api, payments-gateway"}
  }
}
```

> A gold file holds the verified answers for one document, who verified them, and when. dossier never writes gold files itself. Accepting an answer as true is always a person's call.

> eval scores the latest run against the gold set, field by field.

```console
~/quickstart $ dossier eval incident-audit --gold gold/incidents
4 documents · 4 fields · overall 100.0%
  loss_amount        100.0%
  resolution_date    100.0%
  severity           100.0%
  affected_systems   100.0%
```

> One hundred percent, because the stub answers exactly what the gold says. That's our baseline. From here, anything that moves is something we changed.

## 9 · A prompt change, and a regression

> Now let's do what happens in real life. Someone improves the prompt, with one more instruction.

```console
~/quickstart $ echo "When two figures are given, prefer the figure finance reconciled." >> pipelines/incident-audit/prompts/01_extract.md
```

> The plan first.

```console
~/quickstart $ dossier run incident-audit --plan
incident-audit  4 document(s) · model openai:gpt-5.4-mini
compared against 20261011T130756Z-4d36
! extract: prompt changed
1 of 1 step(s) would run · nothing written
```

> It sees the change at once: prompt changed. The prompt is part of every cache key, so this is a new question, and the cache can't answer it.

> So we run it.

```console
~/quickstart $ dossier run incident-audit
run 20261011T130758Z-2004 · ~/quickstart/runs/20261011T130758Z-2004/manifest.json
  extract: 4 document(s) · 0 from cache · 0 failed · 1,648 tokens in · 653 out
```

> And we score it again.

```console
~/quickstart $ dossier eval incident-audit --gold gold/incidents
4 documents · 4 fields · overall 87.5%
  loss_amount         75.0%   <- weakest
    PLAY-1002.md   answered 0.0; gold abstains, so the correct answer was to abstain too
  resolution_date     75.0%   <- weakest
    PLAY-1001.md   '04.03.2026' is not a well-formed date, so it cannot be compared with '2026-03-04'
  severity           100.0%
  affected_systems   100.0%
```

> 87.5 percent. Two fields got weaker, and eval names the document behind each one, and why. For one note, the model answered a loss of zero, where the note says there was no loss at all. For another, it wrote the date as 04.03.2026, which is March in one country and April in the next. dossier refuses to guess.

> And compare puts two runs side by side.

```console
~/quickstart $ dossier eval incident-audit --gold gold/incidents --compare 20261011T130755Z-b7cd 20261011T130758Z-2004
compare 20261011T130755Z-b7cd -> 20261011T130758Z-2004 · 4 documents · overall 100.0% -> 87.5% (-12.5)
  loss_amount        100.0%  75.0%  -25.0   <- regression
  resolution_date    100.0%  75.0%  -25.0   <- regression
  severity           100.0% 100.0%   +0.0
  affected_systems   100.0% 100.0%   +0.0
```

> Both runs are rebuilt from their own manifests and the cache, so no model is asked. The difference is a fact about the prompt edit, not about the model's mood that day. That's the change gate: a prompt edit has to earn its place.
