# PLAY-1001 — Checkout timeouts after the payment gateway upgrade

**Severity:** major
**Resolved:** 2026-03-04
**Systems affected:** checkout-api, payments-gateway

## Timeline

- 2026-03-02 09:14 UTC — checkout starts returning 504s on about one request in
  five. The on-call engineer is paged by the synthetic checkout probe.
- 2026-03-02 09:41 UTC — the payment gateway upgrade shipped the previous evening
  is identified as the only change in the window.
- 2026-03-02 10:02 UTC — connection pool settings are reverted and error rates
  return to baseline within four minutes.
- 2026-03-04 — the fix is rolled forward with an aligned timeout and the incident
  is closed.

## Root cause

The gateway upgrade shipped a connection pool whose idle timeout was 30 seconds
while the load balancer held connections open for 60, so the pool handed out
sockets the balancer had already closed and every request on one of them waited
for the full client timeout.

## Impact

Finance reconciled 214 abandoned baskets against the gateway's own records, a
recorded loss of CHF 18'400.

## Follow-up

- Align pool and balancer timeouts in the shared service template.
- Add a synthetic probe that fails on a closed-socket retry rather than on a 504.
